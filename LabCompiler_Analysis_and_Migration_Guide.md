## 1. Project Purpose & Philosophy

LabCompiler is a **self-contained, portable OpenGL development laboratory**.  
The idea is simple: unzip onto a USB stick (or any Windows folder), run one batch file to set up the environment, and immediately start building GLFW-based OpenGL applications without installing anything system-wide.

### What is included (after extraction)

| Component | Version | Size (approx.) | Role |
|-----------|---------|----------------|------|
| **MinGW-w64** | GCC 14.2.0, MinGW-w64 12.0.0 (UCRT) | ~1.5 GB | C/C++ compiler, linker, make |
| **CMake** | 3.27.1 | ~122 MB | Meta-build system (generates Makefiles) |
| **GLFW** | 3.4.0 (master) | ~43 MB | Windowing & input library |
| **Editor** | Notepad++ 8.6.7 portable | ~27 MB | Lightweight code editor |
| **Bundled deps** | glad (legacy), glm, stb_image, nuklear, learnopengl samples | — | Header-only or single-file libraries |

### What is *not* under version control (see `.gitignore`)

- `MinGW/` — binary compiler toolchain (downloadable from [winlibs.com](https://winlibs.com/))
- `Cmake/` — binary CMake distribution (downloadable from [cmake.org](https://cmake.org/))
- `Editor/` — portable Notepad++ (downloadable from [notepad-plus-plus.org](https://notepad-plus-plus.org/))
- `LabCompiler*.zip` — distribution archive
- `path_backup.txt` — generated by `_SET_PATHS_x64.bat`
- Build directories (`build/`, `mak.mingw.x64/`)
- Compiled binaries (`*.exe`, `*.o`, `*.a`, `*.dll`)
- Old generated `glad.c` files inside each `OwnProjects/Project_XX/`

## 2. The Two Batch Files – Line-by-Line Documentation

### 2.1 `_SET_PATHS_x64.bat` (run **once per shell session** from the project root)

```batch
rem Backup the current PATH to a file
echo Backing up the current PATH...
echo %path%>path_backup.txt

rem Store the base directory
set baseDir=%cd%

rem Display the current file path for the compiler and CMake
echo The current file path will use to our compiler and cmake is:
echo %baseDir%

rem Define directories for the compiler and CMake
set compilerDir=%baseDir%\MinGW\mingw142_64\bin
set cmakeDir=%baseDir%\Cmake\cmake-3.27.1-windows-x86_64\bin

rem Display the defined paths
echo "compilerDir = " %compilerDir%
echo "cmakeDir = " %cmakeDir%

rem Update the PATH environment variable
echo Updating the PATH environment variable...
set path=%compilerDir%;%PATH%
set path=%cmakeDir%;%PATH%
```

**What it does:**
1. **Backs up** your existing Windows `PATH` to `path_backup.txt` (overwrite each run).
2. **Captures** the current working directory (`%cd%`) as `baseDir`.
3. **Constructs** two absolute paths:
   - `compilerDir` → `MinGW/mingw142_64/bin` (contains `g++.exe`, `gcc.exe`, `mingw32-make.exe`, etc.)
   - `cmakeDir` → `Cmake/cmake-3.27.1-windows-x86_64/bin` (contains `cmake.exe`, `cpack.exe`, etc.)
4. **Prepends** both directories to the current shell's `PATH` so that subsequent commands find the local tools first.

**Important:** This only modifies the **current CMD shell**. If you close the window, the PATH changes are lost. You must run this script every time you open a new terminal.

### 2.2 `glfw-master/_GENERATE_MINGW_x64.bat` (run from inside `glfw-master/`)

```batch
@echo off

set currentDir=%cd%

if exist build\ (
    echo build folder exist, if you are using the USB for first time on this PC, this should be deleted!!
    rmdir /s build
)

echo Creating a new build folder...

mkdir build
chdir build

mkdir mak.mingw.x64
chdir mak.mingw.x64

echo Running CMake to generate Makefiles...
cmake -G "MinGW Makefiles" ../../
if %errorlevel% NEQ 0 (
    echo CMake generation failed. Press any key to exit.
    pause >nul
    goto end
)

echo Compiling with MinGW...
mingw32-make
if %errorlevel% NEQ 0 (
    echo Compilation failed. Press any key to exit.
    pause >nul
    goto end
) else ( goto end )

:error
echo !! An error was detected. Not success compilation - press key to continue.
pause >nul

:end
echo Success compilation !! - press key to continue.
cd %currentDir%\bin
```

**What it does:**
1. **Remembers** the starting directory (`glfw-master\`).
2. **Nukes** any pre-existing `glfw-master/build/` folder (the script warns that stale build folders from other PCs can cause trouble).
3. **Creates** a fresh build hierarchy:
   ```
   glfw-master/build/
   └── mak.mingw.x64/     ← CMake runs from here
   ```
4. **Invokes CMake** with the `MinGW Makefiles` generator, pointing back to `glfw-master/` (`../../`).
5. **Compiles** everything by calling `mingw32-make`.
6. **On success**, changes directory to `glfw-master/bin/` (where the executables were placed by CMake).

**Key CMake options hard-wired by `glfw-master/CMakeLists.txt`:**
- `GLFW_STANDALONE = FALSE` — prevents building GLFW examples & tests by default.
- `GLFW_BUILD_EXAMPLES = OFF`
- `GLFW_BUILD_TESTS = OFF`
- `GLFW_BUILD_DOCS = OFF`
- `GLFW_OWN_Projects = ON` — **this is the switch that enables your `OwnProjects/` folder.**
- `BUILD_SHARED_LIBS = OFF` — static linking.

### 2.3 `glfw-master/bin/_RE_COMPILE_x64.bat` (convenience helper)

```batch
cd ..

```

A trivial two-line helper: it moves up to `glfw-master/` and re-runs the full generate-and-build script.  
Useful when you already have a terminal open in the `bin/` folder and want a quick rebuild.

## 3. How to Use This Project (Typical Workflow)

1. **Extract** the ZIP to a folder (e.g., `D:\LabCompiler`).
2. **Open CMD** in the root folder (`D:\LabCompiler`).
3. **Run** `_SET_PATHS_x64.bat`  
   → Your shell now knows about the local GCC 14.2 and CMake 3.27.
4. **Change into** `glfw-master\`.
5. **Run** `_GENERATE_MINGW_x64.bat`  
   → CMake configures, Makefiles are written, GLFW + all `OwnProjects` are compiled.
6. **Executables** land in `glfw-master\bin\`.
7. **Run** any example: `Project_00_glfw.exe`, `Project_01_glfw.exe`, etc.

## 4. Changes Needed to Add More Libraries

The current architecture is a **monolithic GLFW source tree** with your projects tucked into `glfw-master/OwnProjects/`.  Adding a new library requires changes in three places.

### 4.1 Add the library source / headers

Place the library somewhere under `glfw-master/deps/` (for header-only libs) or create a new top-level or sibling folder for larger libraries (e.g., `glfw-master/../Assimp/`, `glfw-master/../Bullet/`).

**Recommended layout:**
```
LabCompiler/
├── MinGW/              (ignored by git)
├── Cmake/              (ignored by git)
├── glfw-master/
│   ├── deps/
│   │   ├── glad/       ← old, to be migrated
│   │   ├── glm/        ← header-only math library
│   │   ├── stb_image.h
│   │   └── NEW_LIB/    ← your new header-only lib
│   └── OwnProjects/
│       └── Project_04/ ← new project using the lib
└── _SET_PATHS_x64.bat
```

### 4.2 Wire the library into a project `CMakeLists.txt`

Open the `CMakeLists.txt` inside the project folder (e.g., `OwnProjects/Project_04/CMakeLists.txt`).  
Add an `include_directories` or `target_link_libraries` call:

```cmake
# For header-only libraries
include_directories("${GLFW_SOURCE_DIR}/deps/NEW_LIB")

# For pre-compiled static libraries
link_directories("${GLFW_SOURCE_DIR}/../SomeLib/lib")
target_link_libraries(${PROJECT_NAME} some_lib)
```

### 4.3 Register the new project in the master list

If you create a brand-new project folder, add it to `glfw-master/OwnProjects/CMakeLists.txt`:

```cmake
add_subdirectory( Project_00 )
add_subdirectory( Project_01 )
add_subdirectory( Project_02 )
add_subdirectory( Project_03 )
add_subdirectory( Project_04 )   # <-- NEW

add_subdirectory ( hw0-glfw )
```

### 4.4 Rebuild

Delete `glfw-master/build/` (or let `_GENERATE_MINGW_x64.bat` do it for you) and run the batch file again.

## 5. Migrating from Legacy glad → glad2

### Current state (legacy glad)

Each project (`Project_00` through `Project_03`) contains a **generated** `glad.c` file (~150 KB each).  
These were produced by the old [glad web generator](https://github.com/Dav1dde/glad) (glad1).

The old setup in `CMakeLists.txt` looks like this:

```cmake
set(GLAD_GL "${GLFW_SOURCE_DIR}/deps/glad/gl.h")
# ...
file(GLOB SOURCES "*.cpp" ${DEPENDENCY_DIR}/include/glad/glad/glad.c )   # BUG: DEPENDENCY_DIR is undefined!
add_executable(${PROJECT_NAME} ... ${GLAD_GL})
```

**Problems with the legacy setup:**
1. `DEPENDENCY_DIR` is **never defined** in these CMake files — the `glad.c` in each project folder is compiled only because `file(GLOB SOURCES "*.cpp" ...)` happens to pick up `glad.c` via the wildcard `*.cpp`? **No** — `*.cpp` does *not* match `.c` files. In practice the line is broken; the project likely compiles because the `glad.c` is manually added elsewhere or the glob silently picks it up from the same directory. This is fragile.
2. Four copies of the same 150 KB generated file bloat the repo.
3. glad1 is deprecated; glad2 is the maintained successor.

### glad2 migration steps

#### Option A – glad2 C/C++ Loader (recommended)

1. **Generate glad2 files** using the [glad2 online service](https://gen.glad.sh/) or the Python CLI:
   ```bash
   pip install glad2
   glad --api gl:core=4.6 --out-path glad2 c
   ```
   This produces `glad/gl.h`, `glad/gles2.h`, and a **single** `glad.c` (or `gl.cc` for C++).

2. **Place the generated files in one shared location**, e.g.:
   ```
   glfw-master/deps/glad2/
   ├── glad/
   │   └── gl.h
   └── glad.c
   ```

3. **Delete** the old `glfw-master/deps/glad/` folder and all `OwnProjects/**/glad.c` files.

4. **Update each project `CMakeLists.txt`**:
   ```cmake
   # Remove the old broken lines:
   # set(GLAD_GL "${GLFW_SOURCE_DIR}/deps/glad/gl.h")
   # file(GLOB SOURCES "*.cpp" ${DEPENDENCY_DIR}/include/glad/glad/glad.c )

   # Add the new glad2 source (one central copy)
   set(GLAD2_SRC "${GLFW_SOURCE_DIR}/deps/glad2/glad.c")
   include_directories("${GLFW_SOURCE_DIR}/deps/glad2")

   add_executable(${PROJECT_NAME} ... ${GLAD2_SRC})
   ```

5. **Update `main.cpp`** to use glad2's new API:
   ```cpp
   // Old (glad1)
   #include <glad/gl.h>
   // ...
   gladLoadGL(glfwGetProcAddress);

   // New (glad2)
   #include <glad/gl.h>
   // ...
   int version = gladLoadGL(glfwGetProcAddress);
   if (version == 0) { /* error */ }
   ```

#### Option B – glad2 Header-Only (even simpler, no .c file)

glad2 supports a **header-only** mode.  If you generate with `--merge` or select the header-only option, you get a single header and no `.c` file to compile.

1. Generate with the header-only profile.
2. Drop the header into `deps/glad2/`.
3. In CMake, simply add the include directory; no extra source file needed.
4. In C++ code, `#include <glad/gl.h>` and call `gladLoadGL(...)`.

**Pros:** Zero generated `.c` files, zero linker objects, smaller repo.  
**Cons:** Slightly larger compile times per translation unit (the loader is inlined).

## 6. Enabling C++26

### Good news: the compiler already supports it

The bundled MinGW-w64 build (GCC 14.2.0) **already recognizes `-std=c++26`** (also aliased as `-std=c++2c`).  
You do **not** need to download a new compiler.

### What needs to change

#### 6.1 Root CMakeLists.txt

Edit `glfw-master/CMakeLists.txt`:

```cmake
# Change this:
set(CMAKE_CXX_STANDARD 17)
# To this:
set(CMAKE_CXX_STANDARD 26)
```

CMake 3.25+ recognizes `26` as a valid value for `CMAKE_CXX_STANDARD`.  
(The bundled CMake 3.27.1 is new enough.)

#### 6.2 Every project `CMakeLists.txt`

Each `OwnProjects/Project_XX/CMakeLists.txt` and `hw0-glfw/CMakeLists.txt` also hard-codes `CMAKE_CXX_STANDARD 17`.  
Update **all** of them:

```cmake
set(CMAKE_CXX_STANDARD 26)
```

Or, better, **remove the redundant standard setting** from subprojects and let them inherit from the root `CMakeLists.txt`.  GLFW's root already sets `CMAKE_CXX_STANDARD`; the subprojects repeat it unnecessarily.

#### 6.3 Compiler flags for bleeding-edge features

If you want the *very latest* C++26 draft features (modules, `std::print`, deducing `this`, etc.), you may also want to add:

```cmake
set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -fmodules-ts")   # if using C++20/23 modules
```

But for most classroom / lab use, simply changing `CMAKE_CXX_STANDARD` to `26` is enough.

#### 6.4 Verify

After editing, rebuild and check the compiler invocation:

```
mingw32-make VERBOSE=1
```

You should see `-std=c++26` (or `-std=gnu++26`) on the `g++.exe` command line.
